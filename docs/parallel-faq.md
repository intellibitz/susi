# Parallel FAQ

Preparation runs in parallel; landing is serial.

### Why did a worktree sometimes compile another worktree's changes?

Worktrees used to share the primary checkout's cargo target directory, and cargo names a workspace crate's build by its path relative to the workspace. An artifact built from another checkout could then read as fresh in this one, so a build or test picked up the wrong version of a package. A guard script (`scripts/target-guard.sh`) and a `cargo clean -p` in the harness gate narrowed this but could not close it.

Every worktree now has a cargo target of its own, copied from a warm snapshot of `origin/main` (`scripts/seed-target.sh`). The snapshot holds only registry and git crates: every unit built from a path (the workspace crates and the vendored path crates) is stripped from it, and again from each copy, so those rebuild from the worktree's own sources; a copy that cannot be stripped all the way is dropped, and the target starts empty. Plain `cargo` is correct, the harness gate runs clippy without cleaning anything first, and builds in different worktrees run side by side instead of queueing on one target. A worktree still linked to the old shared target (made before seeding existed) gets its own as soon as a `git merge origin/main` brings it the seeding (the post-merge hook replaces the link at once and copies in the background; a merge that stops on conflicts runs no post-merge, and the post-commit hook of the commit that concludes it, `git commit` or `git merge --continue`, does the same), and in any case before the first cargo of the finish gate, `sync`, the pre-push hook or `tasks close`. `git worktree add` runs the post-checkout hook, which gives a new worktree a real `target/` before anything can link one; until a susi newer than 0.21.23 is installed, a `susi workflow start` run from a checkout whose hooks predate that can still leave `target` a link, which `scripts/seed-target.sh` replaces. A hook copies the snapshot into a new worktree in the background, and a plain `cargo` does not wait for that copy (it builds cold, and the copy is thrown away): in a worktree just made, run `scripts/seed-target.sh` once, in the foreground, before the first plain `cargo`. It waits for the copy, and returns at once when `target/` already holds a build; the finish gate, `sync`, the pre-push hook and `tasks close` run it themselves.
